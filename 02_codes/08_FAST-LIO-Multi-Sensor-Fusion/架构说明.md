# FAST-LIO-Multi-Sensor-Fusion 架构说明

上游：https://github.com/zhh2005757/FAST-LIO-Multi-Sensor-Fusion

在 FAST-LIO 与 IKFoM 上增加 GNSS 和轮速，是本资料库中同时覆盖 IMU、GNSS、底盘和激光雷达，并且后端仍为误差状态迭代卡尔曼滤波的代码。

相对 FAST-LIO2 的增量：

1. GNSS 量测，以及用 GNSS 航向做自动初始化。GNSS 处理参考 FAST_LIO_SAM。
2. 轮速量测，同时估计轮子外参和刻度因数。轮速模型参考 Zhao、Ji、Wei，IEEE Sensors Journal，2023，doi:10.1109/JSEN.2023.3319345。
3. 作者在 KAIST Complex Urban Dataset 上测试。

## 框架

| 路径 | 作用 |
| --- | --- |
| `src/laserMapping.cpp` | 主节点，组织预测与迭代更新 |
| `src/IMU_Processing.hpp` | IMU 传播与点云去畸变 |
| `src/GNSS_Processing.hpp` | GNSS 位置量测 |
| `src/preprocess.cpp` | 雷达点云预处理 |
| `include/use-ikfom.hpp` | 流形状态，含轮速相关扩展 |
| `include/IKFoM_toolkit/esekfom/esekfom.hpp` | 误差状态迭代卡尔曼滤波 |
| `include/ikd-Tree/` | 增量地图，此仓库已内置，不依赖旁边的 FAST_LIO 目录 |

预测仍由 IMU 完成。一次扫描内，点到平面、GNSS 和轮速作为量测进入同一迭代更新。轮速不是事后松耦合插值。GNSS 在这里是接收机位置结果，不是原始载波紧组合。

## 运行环境

与 FAST-LIO2 相同：Ubuntu 18.04 或 20.04，ROS Melodic 或 Noetic，PCL、Eigen。把本目录放到 catkin 工作空间的 `src` 后编译。KAIST 数据包需按该数据集说明转换成仓库期望的话题，具体话题名以 `launch` 与 `GNSS_Processing.hpp` 为准。

硬件上需要三维雷达、IMU、轮速或编码器、GNSS 接收机，四者时间对齐。KAIST 已经做了车载同步，适合先复现，再换自己的传感器。

该仓库最后一次可见更新在 2024 年，维护活跃度低于 HKU 官方 FAST-LIO。编译失败时先用官方 FAST-LIO2 确认雷达与 IMU，再回到本分支查 GNSS 与轮速话题。
