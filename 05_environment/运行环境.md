# 运行环境

按要跑的代码选择系统。不要试图在同一套原生 Windows 里编译全部仓库。

## 电脑配置

| 用途 | 处理器 | 内存 | 磁盘 | 系统 |
| --- | --- | --- | --- | --- |
| 阅读源码，跑 KF-GINS 与 Matlab | 4 核 | 16 GB | 10 GB | Windows 10/11 或 Ubuntu 20.04 |
| 播放雷达 rosbag 并建图 | 8 核 | 32 GB | 512 GB 可用空间，数据盘单独预留 | Ubuntu 20.04 或 WSL2 |
| 同时保留 KAIST 与 i2Nav-Robot | 同上 | 32 GB | 1 TB 更合适 | 同上 |

固态硬盘用于 rosbag。机械硬盘可以存档，不适合边播包边建图。

## 软件

方案一：

- CMake 3.10 或更高，Visual Studio 2019/2022 的 C++ 桌面开发组件。KF-GINS 自带 Eigen、Abseil、yaml-cpp。
- Matlab R2018b 或更高，用于 KF-GINS-Matlab。
- Python 3.8 或更高，安装 NumPy 与 Matplotlib。

方案二：

- Ubuntu 20.04.6，ROS Noetic 桌面完整版。
- 编译工具：`build-essential`、CMake、`libeigen3-dev`、`libpcl-dev`。
- 若使用 Livox，再按 FAST-LIO README 安装 `livox_ros_driver`。
- RViz 来自 ROS 桌面版。

ROS2 Foxy 只服务于 `06_eskf_gnss_imu_localization`，与方案二无关。新系统若要跑该仓库，优先评估迁移到 ROS2 Humble 的工作量。

本机当前没有 Git。以后更新仓库时可安装 Git for Windows，再用上游地址克隆。现有目录是 2026-09-25 的源码包，不能直接 `git pull`。

## WSL2

在 Windows 上跑方案二时安装 WSL2 Ubuntu 20.04，把数据盘挂进 Linux 文件系统，不要把大型 bag 放在 `/mnt/d` 上播放，跨系统目录的读写会明显变慢。WSLg 用于 RViz。内核用 WSL2，不使用 WSL1。

## 实车硬件

两套方案都需要：

- 六轴 IMU，采样不低于 100 Hz，与其他传感器共享触发或 GNSS 时标。
- 支持 RTK 固定解的接收机和天线。方案一、方案二的现有代码使用定位结果和标准差，不使用原始载波。
- 轮速、编码器或线控底盘速度，方案二的多传感器分支还需要能转换成车体系前向速度。

方案二另需三维激光雷达，扫描内每个点有相对时间戳。雷达与 IMU 的时间不同步时，FAST-LIO 的去畸变无效，此时不要继续调 GNSS 权重。

## 建议的检查顺序

1. 在 Windows 上用 Matlab 打开 `02_codes/02_KF-GINS-Matlab`，运行 `kf_gins`，确认 `dataset1` 出图。
2. 用 CMake 编译 `01_KF-GINS`，使用其 `dataset` 与 yaml，对照 Matlab 位置结果。
3. 在 Ubuntu 或 WSL2 编译官方 FAST-LIO，播放作者提供的小 bag，确认轨迹连续。
4. 再编译 `08_FAST-LIO-Multi-Sensor-Fusion`，换 KAIST 短序列打开 GNSS 与轮速。
